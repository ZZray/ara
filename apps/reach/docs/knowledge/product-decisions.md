# 产品决定及来源

作者：Ray Zhang（Ray）。

日期：2026-11-02（Asia/Taipei）。适用范围：Reach 产品设计与后续实施。

来源为当前 Codex 会话 `01a19608-9d09-7421-be3e-a157a2f3672f` 的用户直接要求。下列内容确认产品方向，不证明已有实现或运行验收。

## 独立项目，产品能力可选

用户要求：

> 对于这个功能来说，qspin 只是一个工具而已，实际上它可以调度任何产品。因此，我们应该新建一个 Git 来进行操作。

此时先建立独立 Git 骨架；仓库归属随后按 2026-11-02 的修正调整。QSpin、LabSlot 等作为可选接入方，Agent 可以不绑定业务产品而使用。

## 迁入 ARA 子项目（2026-11-02）

同一会话中用户明确要求：

> 这个项目放入到，ara-github的子项目吧，然后我们新开会话继续。

随后补充：

> 完成后提交推送，并写交接文档。

当前归属为 ARA 仓库的 `apps/reach/`，由父仓统一管理 Git。原空仓库元数据在本机备份，没有导入历史、建立嵌套仓库或 Git submodule。该要求替代此前单独建仓的安排，不改变产品独立使用、完全控制和复用 Lite/Harness 的方向，也不恢复冻结的 Full Rust 移植。

## 本地 Agent 分析，外部系统提供入口

用户说明本地 Codex 知道源码，分析仍需要本地 Agent；云端只需服务与管理页面，不需要 HandWave 聊天界面。

随后澄清：

> 这是一个通用能力，可以被集成到其他系统，包括控制页面，比如在 lab slot 里面，我增加一个菜单项，点进去以后就会自动认证。

据此，管理服务和页面独立交付，允许复用 LabSlot 的登录。单点登录技术和稳定身份映射仍待设计，同机部署不自动完成认证接入。

## 完全控制，取消权限模式

最初讨论曾提出工具范围、独立权限管理和 Auto / Full Access 模式。用户随后明确修正：

> 默认权限有什么作用？不需要，就是完全控制就行了，没有什么权限。

这条修正替代此前的权限分层建议。当前要求是配对后完全控制，不设置模式选择、默认只读、工具权限开关、角色权限分层或逐次操作审批。此前拟议的授权页改为 Agent、连接、配对与运行记录管理。

用户仍要求登录接入和命令配对，故保留身份识别与配对连接；不把这些重新扩展成工具授权中心。

## 一键安装与命令配对

用户要求：

> 双击一键安装完成……安装完以后直接服务启动。

并要求安装后有命令进行首次或再次配对、命令注册到环境变量。

据此，目标体验为自动安装、注册服务、加入 PATH、启动服务并退出安装器。具体命令参数、配对替换关系和安装技术仍是讨论项。用户明确要求安装后启动服务；服务启动类型（例如开机自启动）由后续安装设计确定，不列为已明确要求。
