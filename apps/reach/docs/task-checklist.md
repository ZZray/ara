## 使用规则

本文件是持续维护的任务状态来源；目标和里程碑见[项目计划](project-plan.md)。任务 ID 保持稳定，依赖写的是必须完成的前置任务。阶段数不代表工作量，不能用阶段平均百分比表示项目完成度。

每项开始时在该项补充负责人、实际状态（进行中/待复核/阻断）、目标版本。阻断时写具体条件和下一步；没有证据不得勾选完成。每项完成需记录交付版本、验收记录路径、结果、实际复核者及未覆盖项。依赖只约束实施顺序，不要求等待无关任务。

验收记录按实际需要存入 docs/evidence/，至少包含任务 ID、日期、源码/依赖/安装包版本、环境、操作、期望与实际结果、产物、结论和复核。原始客户资料、凭据和本机配置不提交仓库。

本次计划文档与既有骨架不计入以下任务的完成数。尚未选定的专项文档用文件名标记，不建立无效链接。

  交付物：从最终源码和安装包执行验收矩阵。

  前置：I06,A06,R07,P05。

  验收：安装→配对→Codex 调用→桌面→委托→页面/SSO→产品接入均有真实链路证据，不借用旧版本结果。

- [ ] **V02 完成运行生命周期故障验收**

  交付物：断网、服务重启、重复请求、取消、更新中断等记录。

  前置：V01,C05,I04,R06。

  验收：可查原操作和实际结果；未知状态保留；不存在把消息送达、取消请求或模型结束当作业务成功的路径。

  交付物：支持版本、不同 DPI/窗口/用户会话和不可操作状态的实际记录。

  前置：V01,T05。

  验收：所声明的环境逐项有证据；锁屏和 UAC 等限制如实说明，不把一台机器通过写成全平台通过。

- [ ] **V04 完成发行依赖和产物核对**

  交付物：固定依赖、许可/第三方声明、组件清单、版本与产物哈希。

  前置：D02,D06,I01,V01。

  验收：开源后端及其传递依赖均核对；Reach/Ray Zhang/RY 标识一致；发行包不包含凭据或客户数据。

- [ ] **V05 准备交付与运维入口**

  交付物：可复现构建、签名/制品流程、部署/升级/恢复手册与故障取证说明。

  前置：V02,V03,V04。

  验收：另一环境可按文档构建和部署；缺失签名或外部条件明确标注，不承诺不可用的发行能力。

- [ ] **V06 完成内测试用与发布判断**

  交付物：内测任务收据、独立验收结论、版本说明及已知限制。

  前置：V05,V01。

  验收：使用者完成一个真实远程协助任务；逐项核对目标后判断交付；实际提交、发布和生产部署另按用户指令执行。

## 清单变更

拆分或增加任务时保留已有 ID，说明范围变化并更新总数及依赖。删除或延期任务必须注明原因和所影响的目标；不能通过缩减清单把未完成的首版功能改为已交付。

本快照中 8 阶段任务数依次为 8、7、7、6、6、7、5、6，合计 52；所有任务均未勾选。
