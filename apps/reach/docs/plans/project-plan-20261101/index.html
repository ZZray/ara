项目目标与完成标准

Reach 为本地 Codex 提供通用远程能力。本地结合源码分析，远端操作系统、桌面和可选产品工具；组织提供管理、连接和按需模型服务。首版建议以 Windows 内测版本为目标，暂称 v0.1，具体版本与技术栈由 P0 明确。

目标能力完成标准验收任务
G1独立运行不安装 QSpin、不接入 LabSlot，仍可登录、配对并从本地 Codex 调用远端工具。C07、A06
G2安装与再次配对干净 Windows 双击安装后服务启动、CLI 可用；再次配对无需重装，兼容升级保留身份和配对。I06、C04
G3完全控制与现场取证配对后直接使用首版文件、命令、进程、日志和 MCP 能力；结果附来源，断线可查询原操作。T07、C07、V02
G4真实桌面操作通过开源后端在交互用户会话截图和操作；服务启动与桌面可操作分别验收。T05、I06、V03
G5独立管理与统一登录管理页面提供 Agent、连接、配对和运行记录；从已登录 LabSlot 菜单进入可自动建立 Reach 会话。A06
G6远端 Agent 委托本地 Codex 提交目标；远端复用 Lite/Harness、组织模型与技能连续取证，返回可独立核对的结果。R07
G7产品可选且可共存无产品、单产品、多产品均可使用；QSpin 等通过既有 API/MCP 接入，资产资料引用原系统。P05
G8可复核的内测交付最终版本有可复现构建、安装包、故障恢复记录、使用说明和实际内测试用证据。V06

本次范围与组件职责

2026-11-01 编制计划与任务清单，当时没有功能实现、安装、部署、提交或推送。2026-11-02 Reach 已迁入 ARA 的 apps/reach；当前归属与交接以 Markdown 文档为准。后续按具体任务推进。Mac/Linux 后续考虑，不建设云端聊天工作台或工具权限中心。

组件部署位置职责边界
service组织服务器安装登记、身份与配对、连接中转、任务事件和收据；接入组织模型配置。Reach 维护自身身份与运行数据，外部资产只保存来源引用。
node被操作的 Windows 机器系统服务、工具宿主、按需交互会话助手、远端 Lite/Harness Host。保存安装身份及执行现场；用户无需配置模型或开发环境。
controller开发者本机reach CLI 与供 Codex 使用的 MCP，共享目标选择、连接和结果读取。本地 Agent 读取源码并判断整体任务；命令与 MCP 共用合同。
admin组织 Web 服务Agent、连接、配对、运行记录及证据页面。可独立访问或由 LabSlot 挂载；不建设聊天工作台。

目标机安装 Node、所需运行时、桌面会话助手、工具后端和配对 CLI；开发机安装 controller 并配置 Codex MCP；组织侧部署 service/admin。源码职责与进程数量分开设计，具体技术选型仍待完成。

安装与使用流程

  1. 部署组织服务建立独立登录入口、连接服务和管理页；按需接入 LabSlot 可信身份。
  2. 双击安装安装目标机组件、注册服务、加入 PATH、启动服务后自动退出；系统 UAC 单独说明。
  3. 命令配对取得配对信息，使用 reach 完成首次配对；再次配对无需重装。具体参数及服务定位待 D03 明确。
  4. 本地 Codex 调用选择目标，直接使用文件、命令、进程、日志、桌面和已接入的产品工具。配对后完全控制，无模式选择或逐次审批。
  5. 按需委托远端任务复用 Lite/Harness 和组织模型现场取证，附证据返回，由本地结合源码判断。
  6. 查看与恢复管理页查看连接及运行记录，断线按原操作 ID 读取收据；未知效果保留，不自动重放。

文档维护与验收流程

  1. 开始前检查依赖在 task-checklist.md 记录负责人、状态和目标版本，引用对应设计。
  2. 按合同实施专项文档负责接口与行为，重要取舍按需记录 ADR。
  3. 保存实际证据区分代码检查、替身、真实进程、桌面、模型和硬件；记录版本、环境、操作、结果及缺口。
  4. 复核后完成填写实际复核者和证据路径后再勾选任务。Run 成功或服务在线不自动代表业务验收通过。

Markdown 是持续维护来源。此 HTML 与输入 JSON 是日期快照，不另维护任务状态。知识库存放有来源的长期决定；临时进度进入任务清单或交接记录。
