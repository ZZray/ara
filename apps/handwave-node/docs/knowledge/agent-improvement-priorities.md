# Agent 能力优化：项目知识、检索与长期使用

日期：2026-10-15。本文记录用户要求与源码支持的优化顺序，不是新功能的
完成清单。适用范围为独立 HandWave Rust Node 与其 Ray/Hub Host；不改变
根仓库 Shared Core 的固定 OMP 移植范围。

## 目标与证据边界

用户要求项目知识库成为 Agent 的能力，并希望同时改善外观、功能和智能。
目标是让 Agent 在新会话中找得到适用的项目资料、说明本次采用的来源、
沿用经过确认的经验，同时保持小型独立程序。知识库入口能打开只证明
管理入口可用；保存、授权检索、节点接收、实际回答和纠正失效须分别验收。

## 两条已有知识链路，不混同范围和存储

| 链路 | 源码支持的现状 | 不应推导出的能力 |
|---|---|---|
| 工作区文件资料（旧 KB） | Hub `apps/handwave/kb.go:121` 保存上传原文件，按 700 字分块；`:73` 的分词包含中文双字；`:236` 按 global/workspace 检索。`apps/handwave/api.go:274` 提供列表、上传、删除、搜索；`:404` 的 `apiAgentContext` 将命中摘录组装进 brief。Web `apps/handwave/web/index.html:152` 和 `app.js:2133` 已有资料管理 | 不是云端共享项目绑定，不具备新 memorystore 的修订/hash/CAS；二进制文件未提取正文，不是完整 PDF/图片知识管线 |
| 共享项目短知识（M1） | `apps/provider/cmd/ray_front/cloud_memory.go:167` 显式绑定项目，`:217` 保存记录；`apps/handwave/memorystore/store.go:138` 接受 `knowledge` 类型，`:455` 生成包含授权项目记录的每 Run 快照。单条文本最多 8192 bytes，最多 32 条且快照 JSON 不超过 32768 bytes | 不是整个仓库自动上传，不是无限资料库；不包含个人 principal、离线 outbox 或节点按需云端 search/read |

两者都已经有请求前上下文入口，不必另建向量服务或把数据库放入 EXE。
管理界面可将共享项目短知识明确作为“项目知识库”的首个可用切片，同时
把旧上传资料称为“工作区资料”。不能只改名称就声称存储、共享与来源均已统一。
迁移旧资料到共享项目必须另有明确范围和验证，不能默默扩大可读设备范围。

Node 对结构化快照的解析在
[context_memory.rs](../../src/context_memory.rs)（基线行 69），上下文作为
来源数据接入；[agent.rs](../../src/agent.rs)（基线行 617–627）区分 brief
与当前请求。云端记录不能授权工具、采纳本地候选或覆盖用户指令。

## 优先级与可观察完成标准

### 外观：让设置与管理的去向明确

保留当前主题与分类设置结构。管理记忆、项目知识应进入可见的管理内容，
显示当前电脑/项目、加载状态、空状态及错误反馈，避免仅把焦点送往隐藏卡片。
共享项目未绑定时显示具体加入步骤。小屏、键盘焦点、Escape 返回和亮暗
主题都属于入口验收；仅截图美化不算管理功能完成。

### 功能：把已有项目知识能力接成闭环

优先复用云端记忆的项目绑定、编辑器、CAS 与 op_id；项目知识模式预选
`scope=project` 与 `kind=knowledge`，不复制一套存储。已有组件在
Go `apps/provider/cmd/ray_front/handwave_memory.js:20–34,51–61,122–132`。

完成标准：用户能进入项目知识、加入明确项目、保存/编辑/撤销，看到结果；
切换设备/会话后不会沿用旧作用域的草稿或响应。用授权项目 A/B 的受控用例
验证共享与隔离，再通过实际新会话验证召回与撤销。知识类型已有测试基础：
Go `apps/handwave/memorystore/store_test.go:98`；API 项目绑定/上下文测试
在 `apps/provider/cmd/ray_front/cloud_memory_test.go:107`。

### Agent 1：中文召回与来源可见

当前云端记忆排序在 Go `apps/handwave/memorystore/store.go:476–493`：
按空白拆 query 后做 substring 匹配，零分记录仍可能进入快照预算。
无空格中文问句的召回相关性因此值得优先验证；这是源码支持的机制，
不是已经测得的准确率结论。先借鉴旧 KB 的中文双字分词、稳定排序和
精确标识匹配，使用项目实际问题集比较召回，再决定是否需要 embedding。

快照已携带 ID、revision、hash、scope。界面应区分“库里可用”与“本轮
实际注入”，并让来源可以展开。注入不等于模型真正采纳，更不等于执行成功。

完成标准：记录中文/路径/标识符查询的来源召回结果、无关记录占用预算、
检索延迟及实际请求体大小；纠正和撤销后不再展示过期来源为当前事实。
未授权设备不能因新排序获得额外域。没有对照数据，不承诺提速或节省比例。

### Agent 2：长会话存储，与上下文压缩分开解决

压缩已经实现，但 [agent.rs](../../src/agent.rs) 基线行 368 在原始消息
达到 256 条时拒绝继续；行 84 的 checkpoint 保存仍序列化完整状态，
16 MiB 为文件边界。派生摘要减少模型输入，并未解除原始历史增长成本。

下一切片应是可恢复的分段原始 journal 与有界活动 checkpoint，保持相同
Session 身份、原始来源和未完成工具 fence。不能简单删除上限，也不能在
恢复失败时新建会话或重放副作用。完成标准包括超过旧边界的真实进程会话、
崩溃/截断恢复、完整工具配对、取消及未知副作用保护，记录磁盘和写入成本。

### Agent 3：候选经验可审、采纳可追踪

[context_memory.rs](../../src/context_memory.rs) 基线行 376 已实现精确用户
管理命令，行 582 注册 `memory_propose`；[agent.rs](../../src/agent.rs)
行 501 的总结可以提候选。候选并不自动成为已确认经验。

优先呈现候选内容、实际来源、适用范围及采纳/撤销状态，再设计上传云端
与重试同步。当前本地候选与云端显式短知识没有完整 outbox 闭环，不能把
本地候选可见称为跨设备学习。完成标准是候选未采纳不影响约束、原来源
纠正/撤销后候选失效、真正用户采纳留收据；模型自报成功不能晋升为已验证经验。

### Agent 4：按需云端检索，留到授权协议明确后

现有 `reference_read/reference_search` 只读本地 active references，见
[context_memory.rs](../../src/context_memory.rs) 基线行 582–641；工具注册
[agent.rs](../../src/agent.rs) 行 625 没有云端按需读取。每 Run 的有限快照
适合首版，小规模知识不需要常驻多 Agent 或复杂图数据库。

后续可增加窄的 cloud search/read/propose 工具，权限取决于真实连接归属或
专用短期授权，不能把执行模型 grant 当记忆写权限。完成标准包括设备/项目
隔离、来源版本、取消、撤销与排队任务交错，以及重复调用的幂等行为。

## 已有能力与明确延期

代码字面搜索、分段/尾部日志读取已经在
[local_tools.rs](../../src/local_tools.rs) 基线行 27 实现；每 Run 读取工作
目录 AGENTS 规则在 [project_rules.rs](../../src/project_rules.rs) 行 21。
优化计划不把这些已有能力重新宣称为新增。

个人主体、自动全盘上传、自动采纳经验、embedding/图服务、常驻后台反思
均非本次必要依赖。项目知识维护文档本身也不会自动成为 Agent 的云端资料；
只有经用户明确选择并走已验证的保存/检索链路，才能宣称运行时可用。

相关设计与边界继续由 [上下文与来源记忆](context-memory.md) 和
[云端知识与记忆](cloud-memory.md) 持有；本页只维护跨 UI/功能/Agent 的
取舍顺序，发布记录应留在证据页。
