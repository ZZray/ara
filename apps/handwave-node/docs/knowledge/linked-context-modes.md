# Linked context, execution modes and reviewed evolution

This product Host is independent from the shared ARA Core and OMP parity ledger.
The browser, Ray and Hub own cloud records, references and device authorization;
the Rust Node enforces local execution modes and persists goal progress.

## Context authority

Device memories stay device scoped. Project records require an explicit project
association; workspace records are labelled **Global (Ray shared)**. Ray's shared
code login does not identify an individual person. This is not personal-account
global memory. Retrieval filters the authorized scopes before ranking English
words and Chinese bigrams, and exposes bounded selected records with revisions.
The snapshot epoch still includes the complete authorized current record set,
including revocations, rather than only search hits.

An explicitly selected @session contributes a bounded public user/assistant-text
projection from the current workspace. Source IDs and server hashes identify the
version. This is browser-history narrative, not native provider replay, current
tool evidence or a grant to execute on another machine. Tools, hidden reasoning,
system messages and attachments are omitted. A changed hash requires a fresh
selection. These references do not switch the native Session.

@machine selects one execution target through an existing, live grant owned by
the current controller. Hub capabilities negotiate the non-renewing connection
operation. A selection cannot approve a new device, extend a TTL, replace another
controller or interrupt an active task. A real matching Node hello completes the
connection; the name displayed in a menu is insufficient.

## Host-enforced modes

`execute` remains the backwards-compatible default. `plan` advertises only
read_file, search_files, list_dir, find_files, system_info, reference_read,
reference_search and experience_search. A second before-tool gate rejects a
forged effectful call. Plan permits only read management commands; it may write
internal audit/session checkpoints. A tool allowlist is not an OS sandbox.

Busy follow-ups inherit the active Session, mode, goal identity and criteria,
including legacy workbench agent-loop follow-ups. A queued message cannot switch
from plan to execute. Mode changes require a new idle dispatch.

`goal` stores bounded criteria, steps, revision and status in the existing native
Session. The model can report progress; a normal Run ends in awaiting_review.
Only the explicit `/goal accept <exact-id>` command accepts the target. Pause and
resume also bind the exact ID. Cancellation and failure remain separate states.
Goals obey the existing per-Run calls, deadline, permission and cancellation
boundaries. There is no background continuation or automatic grant renewal.

## Evolution ownership

A current-Run failed-tool and verified-recovery pair may support an unadopted
experience candidate. Model-provided claims do not replace native receipts.
The user may open the existing cloud editor, review the text and save an
independent device/project/global lesson. This first version is a reviewed cloud
copy, not automatic typed-lineage synchronization: local and cloud revocations
apply independently. A successful Run never promotes its own memory or Skill.
