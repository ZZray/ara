DESIGN · 源码调查与实施建议

QSpin 远程 Agent 设计方案

APP 直接提供设备资料，复用 SDK/Gateway，客户机运行 Lite Agent 服务；增补 QSpin API MCP V2/V3 与 Computer Use 验证。方案稿，尚未实施。

FIELD NOTES

推荐方案与范围

直接复用 APP 数据源，不要求先把全部设备导入 LabSlot。管理页查询 APP 的设备、Gateway 安装信息和已有上报数据；LabSlot 只保存远程诊断所需的关联、权限、Agent 安装记录与任务历史。页面入口由“导入机器”改为“从 APP 选择机器并关联”。

已有 SDK 连接与能力继续复用：对已配对、在线、获得授权的 Gateway，可以调用其实际暴露的查询接口。远程 Agent 增加的是客户机上的完整推理循环、本地日志读取和独立服务生命周期。客户不配置模型，模型路由和额度由云端管理。

验证能力分为 QSpin API MCP V2/V3 和 Computer Use 两条工具路径。Computer Use 首期专注 Windows，优先集成开源 MCP 桌面执行后端；Mac/Linux 后续适配，不从头编写通用桌面驱动。Lite 保留 Agent 循环，Core 补视觉输入通路，Host 负责授权、用户会话与证据；现有 QSpin UI Agent 保留专用 profile 与 recipe。

本次完成标准

给出可回查的现状、职责与数据流、服务安装生命周期、接口草案、分期与验收。本文没有把设计中的接口标为现有能力，也没有连接客户机器或修改部署。

保持不动本轮交付后续实施边界
APP 设备主数据及现有 Gateway 注册/上报源码调查、流程图、接口与页面设计APP 窄接口由其维护方协作；本轮不修改
LabSlot 现有 SDK 配对与 direct/relay 选择数据源直读与最小关联方案不为了诊断全局切换硬件控制模式
内存整理服务、QSpin 采集及硬件流程独立 Agent 服务安装建议首期建议只读诊断；重启、写配置、硬件操作另列范围
Lite Core 的产品无关接口新产品 Host 的接入设计不把产品身份、APP 或 LabSlot 状态写进共享 Core
已确认与建议的区别

安装为服务、复用 Lite、客户免模型配置、LabSlot 管理页面、APP 数据源来自用户要求。只读首期、SDK 到服务的本地 IPC、具体名称和预算是本方案建议。独立 Agent 控制连接仅在既有 Gateway 生命周期或协议不能满足时评估，尚未作为实施授权。

FIELD NOTES

数据源与 SDK 各负责什么

层现有证据本方案如何复用
APP 数据源Device、GatewayInstallation、DeviceGatewayBinding；外部设备详情 API直接查询并显示；避免另一套设备主表和双向同步
SDK 会话LabSlot createSession 创建 SDK server/client，等待 Gateway 握手并校验路由身份复用设备会话、能力发现和已存在的查询方法
执行通道当前 direct 为默认；云端 query 要经过 relay 准入保持明确的通道授权；页面能看到设备不等于云端可调用
客户 Agent现有 HandWave Rust Node 已直接使用 Lite Core复用 Core/Harness 接口；新建 QSpin 专用 Host 和受限日志工具
Windows 常驻现有 QSpinMaintenanceService 有 SCM 和安装闭环复用安装流程经验；独立服务账户、状态目录和凭据

“拿到连接就能工作”对 SDK 已经提供的功能成立。APP 的机器记录帮助发现目标；SDK 的可信会话才承担调用。APP 的设备 ID、Gateway 安装 ID、LabSlot 路由 ID 和 Agent 安装 ID需要有明确映射，不能因为同名、同 IP 或序列号相同就自动合并授权。

源码中的具体差异

LabSlot 当前 createSession 会创建 SDK 会话并等待 Gateway 拨入；并非从 APP 读到一个地址就完成连接。beginCloudOperation 在 direct 模式明确拒绝云端请求。已有配对和连接可复用，缺失时应显示未连接或未配对。

首期优先用现有 SDK/Gateway 连接承载新增的 Agent 任务能力，Gateway 经本机受控 IPC 调用独立 Agent 服务。模型请求仍由 Agent worker 调用统一云端模型代理。这样复用连接、发现和配对基础，新增的任务收据、模型授权与工具权限仍须实现。

后台诊断是待扩展能力

现有 direct 调用由浏览器持有，云端不能直接接管。推荐在既有 Gateway 连接上增加独立授权的诊断控制路由，仅接收 agent.* 命令及事件；原设备 query/command 仍遵守 direct/relay。先验证协议能否复用同一连接，再实现；不把这条新路由描述成现有 SDK 已支持。

服务常驻与连接常驻分开验收

Agent 服务必须独立于 GUI。现有 Go Gateway 桌面部署随 QSpin 启动，所以还需验证 GUI 退出后控制连接是否持续可用。若不满足，再评估 Gateway 受服务托管，或 Agent 复用 SDK 协议建立独立受限连接；这两种均为后续设计选择，不能把 SDK 复用直接视为常驻已实现。

FIELD NOTES

架构与数据流

APP 与 LabSlot 部署在同一服务器是用户提供的部署事实，本轮未登录服务器核验。建议以内部只读 API 访问 APP，同机部署用于缩短链路，不作为共享数据库写权或诊断授权的依据。

推荐结构示意，非运行拓扑证明。APP直接读；SDK/Gateway连接优先复用，诊断路由与IPC待扩展。HTTPS模型请求独立授权。GUI退出后连接存活需验收，不满足时再评估Gateway托管或复用SDK协议的独立Agent连接。

一次诊断的主流程

  1. 选机器

    LabSlot 从 APP 读取目录与详情，展示 Gateway / Agent 的不同在线状态。

  2. 选证据范围

    操作者填写问题、时间范围、QSpin/Server 实例；先查看已有云端上报。

  3. 下发任务

    LabSlot 校验当前权限与安装身份，保存 Task，发有限预算和短期模型授权。

  4. 现场分析

    Windows worker 运行完整 Lite 循环；按需检索本地日志、补读窗口，必要时调用获授权的 SDK 查询。

  5. 回传与复核

    事件、结论、证据片段和缺口回传 LabSlot；Host 核对来源与任务要求，人工可继续追问。

网络与日志范围

无需客户入站端口、RDP 或 SSH 隧道；客户机仍须能访问云端 HTTPS/WSS。原日志默认不整份搬运，但筛选后的片段会进入云端模型和诊断结果，不能承诺日志完全不出网。

FIELD NOTES

直接使用 APP 数据源

LabSlot 增加 AppDeviceSource 适配器：目录、设备详情、Gateway 安装与绑定、遥测/事件等已有上报。浏览器只调用 LabSlot API，服务凭据留在后端。APP 继续维护名称、型号、序列号、归属及上报事实；LabSlot 维护备注、支持人员权限和诊断历史。

从“导入”改为“关联”

  1. 打开远程机器

    直接分页读取 APP 目录；可按序列号、主机名和设备名称搜索。

  2. 预览关联

    展示设备与安装身份、现有 LabSlot 关联、Agent 是否出现；无变化项直接跳过。

  3. 关联并管理

    仅保存 source_instance + source_device_id / source_installation_id 与本地远程机器 ID 的映射。

  4. 后续访问

    资料仍从 APP 读取；本地缓存带 fetched_at 和源版本，失败时明确显示缓存时间。

问题推荐规则
为何还保留少量本地记录任务、权限和安装凭据需要稳定目标；保留引用和必要历史快照，不复制整套主数据
目录接口现状现有 GET /open/devices/:id、/by-sn/:serialNumber 可查详情；该控制器没有服务间分页目录。新增目录窄接口，或由 APP 方提供等价的授权数据源
同机数据库能否直连技术可行。首选 API 避免 Prisma/Drizzle 表结构耦合；若必须只读视图，需固定字段、专用只读账户、版本与配额，不跨系统写表
重复关联与预览变化唯一来源键、idempotency key 和 source revision；确认时重读。冲突行解释原因，其余逐行收据；不静默覆盖本地备注/权限
APP 暂不可用显示带时间的缓存和来源故障，不能将缓存在线状态当当前在线；首期不发新诊断任务，既有任务依其有效租约结束
删除、注销或转移归属标记源停用/待核对；停止新的诊断授权，保留历史。撤销或到期影响在途任务；不能只靠页面刷新处理权限
一台电脑连接多个仪器新管理资源可关联多个 APP 设备，但保留旧 SDK 对同一 installation 与 device 配对的限制。缺安装信息时显示设备条目待关联，不用主机名猜测去重
跨系统权限用来源实例及稳定 owner/member/device ID 显式映射；不用组织显示名或邮箱自动继承 LabSlot 权限。分页、计数、详情、任务、证据和模型上下文均过滤
已有上传数据能用到什么程度

DeviceReportLog.rawBody 是上报请求 JSON；设备详情还组合状态、实验、指标和网关信息。反馈附件属于另一条业务链。只有接口实际授权暴露的内容才能供 LabSlot 使用，不能把数据库存在记录等同于已经有可用的服务间读取接口。

FIELD NOTES

Windows 服务、安装与更新

建议新建 QSpinRemoteAgent 服务，一个签名 Rust EXE 提供 service 和 worker 入口。service 通过受控本机 IPC 接收 Gateway 转来的已授权任务，管理安装身份、任务收据和 SCM 状态；有任务时启动 worker，worker 直接接入 Lite Core/Harness。闲置时不保留大段模型上下文，QSpin GUI 关闭不结束服务；控制连接是否持续在线另行验收。

安装与首次上线

  1. 部署组件

    沿用现有安装器的文件校验、SCM 创建/更新和停止等待；Agent 使用独立目录。

  2. 登记日志根

    定位实际 QSpin 实例和 Server 所在机器；给服务必要只读权限，不按服务账户 AppData 猜路径。

  3. 首次绑定

    服务生成安装密钥，以受信安装/升级发放的短期引导凭据证明身份；服务器校验后关联 APP 对象。

  4. 连接与自检

    经既有 Gateway/SDK 通道报告服务版本、身份与日志可读能力；未联网显示等待连接，不阻断 QSpin 使用。

事项方案
程序与状态Program Files/CIQTEK/QSpin Remote Agent 放二进制；ProgramData/CIQTEK/QSpin/RemoteAgent 放私有凭据、任务与诊断收据
运行账户优先评估 LocalService + service SID 与明确 ACL。其只读访问真实日志/SQLite WAL 必须实机验证，读不到不自动升为 LocalSystem
权限参照内存服务的系统权限和 Users 可读 token 只适用于其原本地用途，不能照搬为远程 Agent 凭据

升级停止接新任务→当前任务有界收尾或记中断→确认 worker 已停→切换签名版本→健康核对；保留上一版本和原身份/收据
回退仅在状态格式兼容时回退程序；不兼容则保留快照并停在待恢复，不让旧程序写新格式
卸载停止任务、删除服务与程序；凭据吊销及本地诊断数据清理结果分别记录。原 QSpin/Server 日志不得随 Agent 卸载删除
资源试点起始建议：每机器并发1、任务10分钟/30次调用；工具片段默认8KiB，上限64KiB且必须受剩余上下文预算裁剪。按游标补读；CPU/内存硬限制用worker Job Object验证，数值压测后定案
服务健康分层

安装成功、SCM 运行、云连接、授权有效、日志可读分别显示。HTTP 200 不能代表现场诊断通过。Windows 服务与交互桌面隔离，需要本地提示时另用受控 IPC，不让服务直接弹普通 GUI。

日志工具与证据来源

来源读取方式结果必须说明
APP 已上报数据授权 API 按设备和时间查询；诊断时附带固定来源快照上报时间、接收时间、数据类型和新鲜度；不标为本机完整日志
QSpin SQLite只读参数化查询；探测既有 schema，短事务与按 ID 分页；不执行迁移建表实例、数据库身份、表/行 ID、时间范围、字段缺失、来源版本
客户端 Server 缓存兼容当前 t_server_log 和旧混表 schema明确标记客户端缓存及缺口；QSpin 关闭后可能不再更新
本机文本日志仅登记目录，按文件身份/代次/偏移有界读取轮转、截断、编码、返回字节、下一游标；不能因无匹配推断无故障
SDK 当前状态/日志接口连接后读 system.capabilities，只调用当前实际暴露且获授权的方法连接目标、接口版本、调用时间与收据；Gateway 自身日志不等于 QSpin/Server 日志
另一台电脑的 Server另部署服务，或验收已有只读 Server 日志接口明确原件所在机器；前端 APP 注册不能凭空读取后端文件

建议工具：list_sources、search_logs、read_log_window、get_runtime_status、get_cloud_report_window。名称是新 Host 接口草案；已有 SDK 方法通过薄适配复用，不重新实现其设备协议。工具输出先做字段级脱敏再交给 Core；文件路径用 source_id 解析，不接受模型任意绝对路径或任意 SQL。

当前 Core 的能力边界

保持 enable_local_tools=false，只注册获授权工具。现有 HandWave Node 默认打开通用本地工具，不直接复制该配置。Core 对 grant 的替换不是完整的日志脱敏方案；凭据、账号与业务敏感字段需要产品策略。

证据片段保留 source_id、机器/实例、UTC 与原时区、行 ID 或字节区间、源版本、截断/缺口与续读游标；原始片段 hash 留现场，云端存脱敏片段 hash 和脱敏规则版本。SQLite WAL 活跃时不得只复制主 DB 冒充一致快照，也不对活动文件使用 immutable 模式。

FIELD NOTES

任务、模型授权与恢复

任务状态（设计）

  1. Queued / WaitingForAgent

    任务已保存，尚未开始；排队也受原 deadline 限制。

  2. Running

    远端已接收并持久化 task_id；由一次或多次 Run 完成检索分析。

  3. NeedsReview

    Host 已检查候选和证据，等待业务接受或人工补充。

  4. Accepted / Failed / Cancelled

    接受须显式记录；失败和取消保留原因，未知结果进入 ReconciliationRequired。

机制实现要求
身份机器安装凭据负责连接；任务执行授权和模型 grant 分开。不得用 Agent 登录替换 APP 现有 Gateway token family
本机 IPC命名管道ACL限定受信Gateway调用身份；Agent服务仍核验云端签发的installation/task、操作者、日志范围与期限。不能仅凭localhost或调用方自报身份接受任务；发现Gateway与普通GUI共用账户时先验专用身份/签名任务边界
云模型LabSlot ModelHost/代理衔接现有中央模型入口；上游长期密钥只在服务器。任务 grant 绑定操作者、资源域、machine/installation、Task/Run、model/protocol、预算与 expiry
复用 HandWave复用默认模型路由与短期授权思路，采用明确的任务绑定；旧 default grant 与 smart 路径的检查强度不同，不能原样移植后声称隔离已完成
收发task_id + attempt/run_id + event_seq；收到任务先落收据再 ACK，重复消息返回既有状态。start/cancel/resume为command，不能套现有query瞬断自动重试；status/events按task+seq幂等读取
页面与断线推荐任务在服务持久接收后按有限租约执行，页面关闭只停止观察；若首个原型仅用浏览器direct提交，则事件本地落盘、重开按seq补读，后台新派发/云端持续归档仍未满足
控制链路失效正式后台诊断路由与浏览器连接分开。控制路由失效时不接新任务，已有任务仅在原执行/模型租约内运行并保存事件。云端显示状态待确认；取消在恢复后核对，不提前宣称已停止
租约与撤销不自动续权或延长原Task截止；到期停止新调用。联网时响应撤销；离线时不能保证即时收到撤销，窗口上界为既有短租约剩余时间。首期不设无限后台任务；完全断网不能调用云模型
链路资源SDK/Gateway共线只承载有界任务控制、摘要和分页事件，模型token流经独立HTTPS代理；限帧大小和事件速率，验证不会阻塞已有采集/控制流
resume重启后先读收据并核对授权、Session 与开放调用；未知效果不重放，依据 Harness 的 reconcile_resume 合同决定恢复或拒绝
完成判定Harness AwaitingHostAcceptance 不是业务 Task 已接受。验证引用可定位、输出完整性/缺口与问题范围；根因不能只靠模型自述判通过
能力与验收

Core/Harness 已有循环、Session、预算、取消、检查续作和受控恢复证据。任务61仍未全量通过，真实综合长任务覆盖不足。首个客户诊断试点必须独立验收，不把之前的能力试验当本产品上线证明。

诊断到验证的闭环

每次验证按同一任务留证

  1. 固定目标与判据

    记录机器、安装、QSpin/Server与API/UI profile版本；提出可验证假设，确定本轮操作和通过条件。

  2. 取得基线

    API读状态/数值，保存日志窗口；需要UI时读取目标窗口/控件树并截限定区域。记录各自时间与新鲜度。

  3. 执行获准步骤

    优先API；需要证明界面行为时执行批准UI recipe。命令只派发一次，有operation则保存原intent与受理回执。

  4. 核对后置结果

    V3等待原operation终态；UI重新观察/截图；按需求核对新日志、文件或数值，标明未覆盖或未知。

  5. 形成验证收据

    Host按预先判据输出通过/失败/覆盖不足/结果待确认，附原始证据引用；模型给解释，业务Task仍待明确接受。

验证层级能证明什么不能据此声称
只读 API + 日志当前状态、数值、错误和时间范围的交叉核对历史根因必然成立，或已修复
副本/离线验证固定样本、配置副本、文件输出与数值判据匹配实际仪器行为或客户现场通过
UI观察/受控输入真实目标窗口、实际操作前后状态和指定recipe结果截图正常就代表业务/硬件完成
实机业务验证获准设备动作的真实回执、终态、输出和领域判据mock、MCP成功或operation accepted可替代此层

API 与 UI 可能读取同一缓存，二者一致不自动构成独立证明。需要验证输出时增加实际文件、数值或设备回执。当前 combined 数据绑定桥未实现，首期在Task层按时间顺序汇集证据，明确时间差，不宣称API/UI原子快照或原子联合验证。
