### F1 (High): the CLI never uses the discovered `SYSTEM.md` or `APPEND_SYSTEM.md`

- **Where:** `crates/ara-cli/src/main.rs:466-468`. The CLI passes only `--system-prompt` and `--append-system-prompt`.
- **Why the content is lost:** `build_system_prompt` loads `SYSTEM.md` into `systemPromptCustomization`, but only `custom-system-prompt.md` renders that field. With the default template the content never reaches the model.
- **Upstream `main.ts:1037-1105`:**
  - `systemPromptSource = parsed.systemPrompt ?? discoverSystemPromptFile()`, and the append prompt likewise with `discoverAppendSystemPromptFile()`.
  - Both go through `resolvePromptInput`, then `applyResolvedSystemPromptInputs`, which sets `customSystemPrompt` and `appendSystemPrompt`.
  - Discovery uses `findConfigFile` (`config.ts:128-156` and `findConfigFile`). The first existing file wins, in this order:
    - project: `<cwd>/<base>/<name>` for bases `.omp`, `.claude`, `.codex`, `.gemini` (ARA: `.ara` first);
    - user: the native user dir (`~/.omp/agent`, ARA `$ARA_HOME/agent`), then Claude's config dir, `~/.codex` and `~/.gemini`.
  - The project dir is exactly `cwd`, not a walk up the tree.
  - User entries other than the native one are skipped unless `isUserSourceEnabled(name)`. `LoadContext::is_user_source_enabled` already ports that check.
- **Fix:**
  - Add `Discovery::find_config_file(cwd, name, level)` in `ara-discovery`.
  - In the CLI, use `--system-prompt` or else the discovered `SYSTEM.md` path, and `--append-system-prompt` or else `APPEND_SYSTEM.md`, both through `resolve_prompt_input`.
  - Make `--append-system-prompt` keep the last value, as upstream does (`flag-tables.ts:169-171`). It is currently repeatable and joined.
  - Fix the comment at `main.rs:422`.
- **Tests (e2e through `ara`):**
  - project `SYSTEM.md` replaces the default prompt;
  - user `SYSTEM.md` is used when there is no project file;
  - `--system-prompt` overrides both;
  - `APPEND_SYSTEM.md` is appended;
  - the content renders once. `system_md_used_as_custom_prompt_renders_once` already covers the library side.

### F2 (High, safety): the bash `skill://` expansion does not exclude backslash in unquoted tokens

- **Where:** `crates/ara-tools/src/internal_urls.rs:201`. The unquoted class ends in `` `\;&|<>($] ``, where `\;` is only an escaped `;`. Upstream `bash-skill-urls.ts:14` has `` `\\;&|<>($] ``, which also excludes a backslash.
- **Trigger:** `echo skill://demo/x\" '" ; touch M ; "' skill://demo/y\"`, with skill `demo` loaded, runs `touch M` after expansion. It must stay a literal.
- **Second symptom:** `cat skill://demo/a\ b` becomes `cat '/…/a\' b`; upstream gives `'…/a'\ b`.
- **Approval gap:** the `before_tool_call` approval sees the unexpanded command.
- **Fix:** write the class so the backslash survives (for example `\x5C`), and check the committed bytes.
- **Tests:** both commands as string tests, plus a `BashTool` test that asserts the marker file is not created.

### F3 (Medium, safety; upstream has it too): quoted tokens nested inside quotes are expanded

- **Where:** `internal_urls.rs:304`. Quoted tokens skip `is_inside_shell_quote`, as upstream does (`bash-skill-urls.ts`, `isEmbeddedInQuotedText`).
- **Trigger:** `echo '"skill://demo/x;touch${IFS}M"'` runs `touch M`.
- **Fix (intentional difference):** skip any token whose start lies inside a shell quote, quoted or not. The upstream `expandInternalUrls` cases in `crates/ara-tools/tests/skill_urls.rs` must still pass. Leave the strict `expandSkillUrls` port unchanged.
- **Record:** add this as an intentional difference in the evidence, with a marker-file test.

### F4 (Medium): the reminder state is keyed by index, not message identity

- **Where:** `crates/ara-context/src/reminder.rs:44-51` and `transform`. The `injections` and `controls` maps use indices and `seen` is a count.
- **Upstream (`session/date-cwd-reminder.ts`):** `#injections: Map<Message, Message>`, controls anchored to message objects, and `#seen: WeakSet`.
- **Trigger:** after a reminder attaches to U2, the host rewrites the tail (`[U0, A, U2']`). The model then gets stale U2 content, and after a shrink new user turns are missed.
- **Fix:**
  - Store each original next to its injection.
  - Substitute only while `messages[i] == original`, and validate control anchors the same way.
  - Reset on any mismatch, or when the transcript is shorter than `seen`.
- **Tests:** rewrite; shrink; the developer-turn fallback (currently untested); and that the fallback's wire role follows provider support.
