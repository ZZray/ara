## Architecture and this change

CLI host → context/skill discovery → Agent loop → AI provider → tool effects
→ Session journal. Testkit supplies controlled HTTP/SSE upstreams for host
tests. This follow-up adds a provider-local explicit strict-tool override so
the public stream and Agent can use a controlled fake upstream. Its default
keeps the existing official-route selection. Agent, Session and CLI production
code were not changed; custom-route requests remain non-strict by default.

The fixed OMP allowlist, schema eligibility and budgets now produce
`strict: true` on canonical official Anthropic routes when representable.
Clear strict-related HTTP 400 errors retry once with non-strict tools before
stream Start; unrelated errors do not. On follow-up `394061b`, the AI suite
passed 120 unit, 31 Anthropic HTTP, 48 Chat HTTP and 29 Responses HTTP tests;
Agent's six test groups passed, including 37/37 `agent_loop` tests. Anthropic
CLI tests passed 9/9 on the custom route. A classified strict 400 recovered
through public `stream` and Agent with one in-memory test tool effect and
matching follow-up IDs. The two independent Codex plan/diff review rounds
completed; the latest diff review found no high-confidence defect. The full
verifier still fails the existing Windows Bash deadline assertion (38/39 CLI
e2e), so this stays WIP. See the
[receipt](../evidence/ai-anthropic-strict-tools.md).
