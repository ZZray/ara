The next fault pre-review found that pinned Tokio 1.53.1 prefetches up to
32 directory items inside `read_dir().await` and caches
`std::DirEntry::file_type().ok()`. A type injector must retain EIO after
forcing the chosen entry to `DT_UNKNOWN`: the first prefetch call may
discard the error, and public `file_type` retries when the cache is empty.

errors during that prefetch are buffered for `next_entry`; receipts must
describe OS post-open/prefetch failure accurately, rather than claim that
the fault occurred after Tokio's `read_dir().await` returned. This is
reviewed dependency-source evidence, not a completed injection experiment.

### Directory fault plan: independent pre-review completed

`resource_scan_plan` verified Tokio 1.53.1 and Rust 1.97.1 std source
commit `8bab26f4f68e0e26f0bb7960be334d5b520ea452`. For Linux GNU,
`sys/fs/unix.rs:876-887` uses `readdir64`; `DT_UNKNOWN` enters metadata
at `1121-1130`, using weak libc `statx(dirfd,name,...)` then
`fstatat64` (`1064-1081`). The weak syscall wrapper supports interposition.
Actual runner ABI and hook hits remain untested and must be checked before
counting injection evidence.

The reviewed implementation boundary is three new test-only files:
`scripts/ctx_skill_directory_fault.c`,
`scripts/ctx_skill_directory_fault_trial.py` and
`.github/workflows/ctx-skill-directory-fault.yml`. Use an isolated
Ubuntu 24.04 x86_64 GNU runner and the checked Rust 1.97.1, or recheck the
runner's exact std source. Build the real CLI and a shared C shim with
strict warnings, `-fPIC -shared`, pthread and `-ldl`; save compiler/libc
versions, dynamic symbols, resolved original functions and binary hashes.

Run three cases through that same CLI: observe-only control must return
the complete listing; enumeration must return at least one real entry
before NULL/EIO; type must force one real entry to `DT_UNKNOWN` and retain
metadata EIO for both prefetch and public `file_type` calls. Missing
symbols, zero injection hits or successful partial listings are failures,
not skips. Register only successful `opendir` calls for the exact fixture
path after the fake upstream creates a per-case arm-file on its first
model request. Match metadata by registered dirfd and fixed basename,
not by the directory's initial metadata call.

The shim should wrap only `opendir`, `readdir64`, `closedir`, `statx` and
`fstatat64` for the reviewed GNU path. Use `RTLD_NEXT`, a finite handle
table, mutex, thread-local recursion guard and raw syscall logging to an
inherited fd; preserve original errno and set injected EIO last. Do not
add guessed wrappers until the actual ABI/source probe calls for them.

Each case has a fresh home/Session/server and exact limits: two model
requests, one `read` receipt, 30-second Run and 40-second process bounds.
The second request verifies the tool text; the Session separately verifies
`isError` (Chat projection has no such wire field). Save hook phases/hits,
events, requests, journal, fixture manifest and summaries on success and
failure. This plan is ready for implementation; none of its Linux probes
or injected cases has run yet.
