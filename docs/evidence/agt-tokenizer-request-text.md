# AGT-TOKENIZERd: prepared request message text (WIP)

Fixed OMP source: `596f2da7101178214aa27a753529d15e6b7ad91d`, `packages/ai/src/providers/openai-completions.ts:755,1642-1925` (`buildParams` and `convertMessages`). ARA's OpenAI-compatible adapter builds one JSON `params` value, then serializes and retries that same value. This point adds an ARA diagnostic after `build_params` and before HTTP POST. OMP does not have this observer; it is an intentional host diagnostic, not a claim of full upstream parity.

The observer counts only the string `messages[*].content` and text `messages[*].content[].text` fields in that final value. It uses the host-selected Claude family and tokenizes each wire text field separately. Therefore it sees converted system prompts, assistant text concatenation, tool-result joins, synthetic text and non-vision image placeholders. It excludes tool definitions, tool-call names and arguments, image payloads, role/ID/framing fields, and any proxy-side transformation. It does not provide total prompt tokens, a token lower bound, a context fit verdict or compaction trigger. Unknown tokenizer, unsupported content shape, count overflow and a diagnostic limit are explicit statuses. The limit is 1 MiB of text or 16,384 text fields; this bounds synchronous optional counting. `coverage_complete=false` marks partial metrics after a shape or size stop.

`StreamOptions.request_text_observer` is opt-in and uses a bounded Tokio channel with `try_send`; closed/full receivers do not change model delivery. The observer exposes a dropped-event count. Reports contain numeric counts, booleans and a process-wide sequence only; they do not carry request content, route, model ID, headers or credentials. A report means **prepared**, including when cancellation or HTTP failure prevents delivery. Transport retries share one prepared report. The reference CLI exposes `--report-request-text-tokens` on stderr and reports any dropped observations. The Agent event contract and context/compaction logic are unchanged. To avoid two Claude-family mappings, the selected-family fragment counter now lives in `ara-ai` and is re-exported at its prior `ara-agent::tokenizer` path.

The independent design review compared pragmatic, architecture and performance approaches. The independent diff review confirmed that measurement and POST use the same `params`, then identified partial-metric and silent-drop diagnostics; both were addressed with `coverage_complete` and a dropped-event counter. A later review found that reading drops before channel closure could miss a late failure; a stats handle without a sender now reads the count after the CLI waits for closure. The bounded CLI FakeUpstream test covers normal completion. Full `python scripts/verify_backend.py` was attempted on Windows and failed during workspace Clippy: Unix-only symlink tests in `ara-discovery` do not compile, and a vendored `pi-edit` test has an existing unused import under `-D warnings`. The suite did not reach all tests. Strict CLI Clippy likewise stops in existing `ara-tools` Windows warnings. Long-input cold/warm timing and a real-model context-overflow task are still open. This point remains WIP and does not satisfy A3 acceptance.
