Agent Core 编码与逆向能力研究

模型、运行框架、工具、环境与验收的分工；精简 Rust Core 的增强顺序。

FIELD NOTES

建议先增强哪些能力

建议保留精简 Rust Core，优先做“定位代码 → 可靠修改 → 执行验证 → 根据失败继续修复”的完整闭环，再加外置逆向分析后端。让模型看见准确证据、能采取有效行动、能判断结果，是本轮研究的共同方向。

层次实际负责什么对我们的含义
模型理解需求、生成代码、推理不完整证据、选择下一实验框架能帮助模型发挥，但不能把较弱模型变成同等能力的强模型
Agent运行框架循环、上下文选择、权限、恢复、预算和终止减少漏步骤、上下文污染、无效重试和错误完结
工具找定义/引用、修改、编译、测试、反编译、调试给模型可用且可检验的观察和动作
环境源码、编译器、依赖、调试权限、持久工作目录同一个工具接口在环境缺失时仍无法完成任务
验证与经验独立结果检查、来源追踪、跨任务复用成功必须由产物证明；经验需要验证与范围，不能自动改成事实
研究结论，不是新版本验收

已核对源码与官方资料；本轮没有改变运行时代码、安装外部工具、调用真实模型或部署。下面的新增接口、阶段和门槛都是建议，尚未实现。

Claude Code公开了什么，强在哪里

用户给出的anthropics/claude-code仓库公开了插件、示例、变更等资料。当前LICENSE.md为保留所有权利并引用商业条款；它不能作为整套运行时可自由移植的开源基线。本轮没有对全部历史版本作法律或源码完整性审计，不能声称历史上从未公开过源码；意外泄露或可下载源码也不等于授予开源许可。

官方可观察机制是：工具结果回到模型循环，按任务查文件、修改并跑测试；MCP、Skills与子Agent扩展能力，上下文按需加载并压缩。它同时依赖模型的编程与工具使用能力。仅凭官方文章，无法给模型、训练、提示词、框架分别分配贡献百分比。

可参考机制如何帮助完成工作应避免的误读
任务直接面对真实环境读源码、运行测试，再根据反馈决策会写解释文本不代表修改已落地
工具接口清楚且输出有用减少参数误用和无关输出工具越多不必然越强

实际编码能力由什么组成

  1. 确认任务和约束

    理解已有行为、范围、用户WIP及结果标准

  2. 定位与理解

    目录、文本搜索、符号定义/引用、相关规则和失败日志

  3. 设计并修改

    生成小范围修改，绑定读取版本，检查差异

  4. 运行与观察

    语法/类型检查、编译、测试或实际程序行为

  5. 修复并接受

    按错误归因修正，独立检查产物，保留未覆盖事项

模型真正生成的是代码、补丁或脚本；文件工具把它写入环境，执行工具运行它，编译器/测试/运行结果提供反馈。Python、PowerShell、cmd、sh不是四套“智能”，主要是执行器、转义、编码、退出码和环境差异。语言知识与算法判断仍在模型一侧。

因此下一步应同时改善定位、修改和验证，而非只扩充Shell指令。增加LSP或AST能让定位更准确；有版本检查的补丁能减少改错文件；诊断和完整日志能帮助模型继续修复。对当前库，这些比重做聊天UI或叠加通用规划角色更直接。

普通exec/run_script的当前实现保留有界输出，超出部分可能丢弃；原始会话日志保存的是已返回内容，不能补回从未保存的中段stdout。后续应按任务保存带配额的完整输出产物，模型只读摘要与局部范围。managed Job日志是另一路径，不能用它证明所有普通执行都已保留全文。

逆向能力需要工具，也需要推理与验证

逆向通常从缺少源码的产物出发：先确定格式/架构/依赖/字符串，再找关键函数与引用，推断数据结构和控制流，最后通过受控输入或调试观察区分假设。反编译工具提供近似表示，模型负责组织证据、提出可验证推断。反编译伪代码不是恢复出的原始源码。

  1. 固定分析对象文件SHA、大小、架构、编译/加载信息；动态地址用模块+RVA/加载基址关联，处理ASLR
  2. 静态缩小范围导入导出、字符串引用、函数列表、xref、反汇编和按函数反编译；分页而非全程序dump
  3. 形成行为假设记录推断、依据、未知类型和能区分正反例的输入；允许“不知道”
  4. 动态取证在授权目标/隔离环境中运行、断点或插桩；保留事件、输出和样本输入
  5. 验证与沉淀用未见输入验证恢复的算法/格式；笔记绑定样本hash、工具版本和证据，不能只抄模型结论

逆向工具输出中的地址、函数名和类型会随重分析变化。接口应带样本hash、项目revision、函数地址、分析选项与工具版本。缓存能复用分析，但不能跨不同文件或版本静默复用。

LLDB该主线文档明确：MCP会发现同机其他会话，对close有ownership限制，但command可驱动发现的其他会话。因此不能把自动发现作为授权。若选择它，宿主须只接自有会话并隔离运行账户/注册目录；这不是原桥已经实现ARA多业务隔离的证明。

同一LLDB提交存在文档/实现漂移：mcp.md称新会话async，但Tool.cpp的DebuggerCreateTool::Call明确SetAsyncExecution(false)，要求resume等待停止。当前创建路径应以源码为准；发现的外部会话和目标输出仍须分别观察，不能把一个默认值外推到全部会话。主线源码存在也不代表本机发行版已含此入口。

LLDB创建路径实际同步设置

建议的动态状态合同为Loaded → Running → Stopped → Exited/Detached/Lost，stack/locals绑定stop epoch。取消等待不代表目标已终止；step/resume结果未知先观察原会话，不静默新建后重放。静态注释/重命名也会修改分析项目，须单独写入授权与revision。

许可与体积要一起考虑：Ghidra为Apache-2.0，radare2/Rizin主要LGPL（组件另核），Frida引擎使用wxWindows许可而非文档的MIT，x64dbg的GPL正文含插件例外，LLDB为Apache-2.0附LLVM例外；WinDbg按Microsoft条款。实际复制/分发需再次核选定版本完整依赖。本轮仅研究，不打包这些项目。

操控能力的优先级

控制方式适合的任务限制与选择
结构化API/LSP/调试接口定义引用、诊断、分析函数、调试会话状态优先使用；绑定文档/会话版本，避免拿过期结果修改
CLI与显式脚本构建、测试、批量数据转换、安装环境、工具组合当前Core已具备；复用它，输出应可检索，命令成功不代表业务成功
DOM/可访问性树网页交互、运行应用验收可外置Playwright；权限和用户登录态由宿主控制

编码和静态逆向通常不需要先做完整桌面computer use。GUI编辑器和逆向界面可以留给人看；Agent优先走headless、CLI或结构化接口。遇到图形专有流程再补桌面适配，避免用逐次截图点击替代本来已有的API。

Playwright MCP官方README已同时讨论CLI+Skills与MCP的取舍：简短CLI适合常见编码流程，持续状态与结构观察适合MCP。不能把“全部改成MCP”当统一效率优化。

机制值得借鉴的部分适用边界

自我进化建议定义为可审的适配循环：观察失败 → 形成带来源候选 → 在隔离用例及留出任务验证 → 宿主/审查采纳 → 可回滚版本。自动下载工具、保存经验、修改自身源码分别是不同权限和验收，不应合并成“已能自我进化”。

省token与缓存应如何做

  • 少读：按目录/符号/引用定位，再读相关片段；搜索要报告范围与截断，不能以零结果证明全局不存在。
  • 少传：编译、调试和批处理在工具端运行，返回差异、失败诊断和证据句柄；完整原件留在受控存储。
  • 少往返：独立只读操作可并行，批量处理用脚本/API组合；有依赖和副作用的步骤保持有序。
  • 稳定复用：稳定规则与schema放在稳定前缀，动态进度放后部；历史压缩前先确认必要，不为命中率保留无关材料。
  • 少重试：区分参数错误、环境缺失、真实编译错误、模型/网络失败；相同证据下不无限重跑，未知效果先核对。

DeepSeek官方Context Caching默认启用，按可复用前缀尽力命中，usage提供prompt_cache_hit_tokens和prompt_cache_miss_tokens；当前文档已具体说明前缀单元的复用条件。本项目经CAS、B.AI或OpenRouter等链路时，字段是否透传、模型是否同一上游、缓存是否保持都需分别实测。官方直连行为不能直接替代理解中转商。

缓存命中可降低重复输入的计算/计费，不代表输入token在语义上消失，也不提高算法理解能力。当前Core从适配器拿不到零与缺失的区别，故不能可靠计算全量命中率或真实账单。保留这条边界，先补原始usage字段存在性，再按具体provider验证。

模型选择仍由宿主控制。本研究不改变用户已选择的Auto随机策略；能力对照实验单独固定模型、路由、参数和预算。生产随机模型的两次结果不能直接比较成框架优劣；跨模型缓存也不能假定共享。
