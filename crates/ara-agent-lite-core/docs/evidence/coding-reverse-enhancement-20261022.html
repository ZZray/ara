增强方向

整体目标仍在进行

整体目标继续。原Full公共入口S3多文件C++任务已限定通过原58项与独立重编；公共层已有显式有界长度续作，该阶段39项检查通过。本轮再完成文本连续性消费示例：当前包52项通过，真实模型双进程累计8次调用、两进程合计18.56秒。新长度功能的真实模型恢复尚未执行。此前Lite失败、Full首轮Length与第二轮off预算失败全部保留；真实逆向、通用稳定收益、产品和依赖审计仍未验收。

Core 本身用 Rust 实现。当前编码验收题用 C++，检查跨文件修改、真实编译和测试反馈；静态逆向题使用自有 C 程序编译的去符号样本，尚未验证 C++ 对象模型、虚表或异常处理的逆向。

编码能力需要模型理解需求、定位代码、生成修改并解释执行反馈；运行框架负责把这些步骤连起来。操控能力提供观察和行动入口，其价值取决于能否拿到足够证据、准确修改目标，以及检查实际结果。强模型、可靠工具、适当上下文和验证环境共同决定表现，公开资料不足以把 Claude 的优势归因到某一个组件。

逆向分为源码理解、黑盒行为或协议推导、二进制分析。前两类可以大量复用编码工具；二进制分析还需要反汇编、反编译和调试后端。工具给出观察，模型提出假设并选择区分实验，留出输入和运行结果检查推断是否成立。安装了分析工具，不能直接认定 Agent 已具备可靠逆向能力。

本次交付范围

保留现有编辑、Run/Job、权限及完整版 OMP 基线。独立 Lite 依次增加普通进程输出归档、可选源码定义和 GNU 静态观察，以及宿主显式生成策略。接口、模型采用、任务产物和稳定收益分别验收。

可选 null 参数的原生调用契约

read_file、source_symbols 和 binary_inspect 的可选字段可用 null 表示未使用。每个工具只移除自己的可选字段白名单，随后执行原解析。必填字段和未知字段不被这一处理吞掉；非空冲突、错误指纹和分页保护仍在。编辑及其他工具不变。

首批增强：长输出归档与回读

原 exec/run_script 为控制模型上下文而保留限额片段，其余字节从管道读走后丢弃。编译错误或分析结果如果位于被删中段，后续只能重新执行或改命令取证；对有副作用的命令，重跑可能不合适。新 capture_dir 将原始输出和模型摘要分开。

json
{"language":"python","script":"import subprocess\nraise SystemExit(subprocess.call(['python', 'check.py']))","output_limit":4096,"capture_dir":"build-output-001"}
  • 只在调用者显式提供 capture_dir 时启用。最终目录必须全新，父目录必须已存在；准备失败不启动命令，不覆盖、复用或递归删除已有目录。
  • stdout.log 和 stderr.log 保存精确原字节，每流最多 8 MiB；超额继续排空并记录 observed_bytes，收据明确 quota_exceeded 和 complete:false。配额不足不把 exit 0 改成进程失败。
  • 收据包含实际保存字节数、观察量、EOF、SHA256 和错误。哈希按实际成功写入更新，并在收据生成时读回核验；归档 I/O 错误保留已知进程状态，不得盲目重放命令。
  • 模型摘要和 Host 事件都预留收据空间，避免 Host 再次截断丢失归档位置。省略新字段保留原工具格式；公共 run_shell 签名不变。
  • 超过 1 MiB 的 UTF-8 日志使用 read_file offset/limit/tail；其他编码由 run_script 显式解码。raw log 未做自动脱敏，留存和清理由调用者管理。
  • 取消沿既有 AgentError::Abort 语义，工具文本收据不保证继续送给模型，已写原文件仍在已知目录。同步磁盘 I/O 没有独立硬截止保证，慢盘、路径替换和之后的文件修改不受此机制消除。
原始输出捕获实现进程与工具接线显式脚本接线真实 Host 验证器

预览上限与当前 Run 的上下文预算是不同约束。128 KiB 预览可能超过较小模型目录分配的保守字节预算；输出归档不会放宽该预算。长任务仍需选择适当的 run_script output_limit，后续应单独评估按 Run 预算控制摘要的接线。

首批可选输出归档机制与声明的正常/失败行为已验证，真实模型走通了一次明确引导的归档回读修复。没有同模型旧版/新版的成对统计，不能给成功率提升百分比、不能接受一般逆向能力，也不能据三个有限任务宣称追平 Claude。
