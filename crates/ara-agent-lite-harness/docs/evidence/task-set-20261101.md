## 目标、版本与边界

在现有 Lite Harness 上提供可选的接待与后台执行分离：立即启动独立 Task，向明确
原任务投递已授权消息，取消并等待原效果结算，按完成顺序交回原结果。
基线为 `e229fb9ab800b46313047b89b73ac41e60c9efb4` 加本轮工作区变更；最终源码哈希见
[snapshot.json](task-set-20261101/snapshot.json)。既有 HandWave 和根 docs WIP 排除。

思想来源为 DeepSeek
[原型固定版本 6337fc823ce](https://github.com/deepseek-ai/dsh-superagent-prototype/tree/6337fc823ce20251c8de8085948165c81aaa701e)
的接待/执行分离与后续消息归属。没有复制其代码，没有实现整套 Super-agent。
既有 `tools/ara-lite` 持久协调服务不变；本轮是有界批次 TaskSet。

实现保留原 Session、ModelHost、steering Arc、Task 总预算、Host 复核、未知效果与
业务验收边界。不同 Task 共用 steering Arc 会拒绝；已完成身份不回收批次槽。
消息仅承诺排队，在轮次边界消费；模型已停止而 Host 仍验收时，消息可能最终未应用。
完整使用和限制见 [接入说明](../task-set.md)。

## 原生示例和真实模型

同一 source-built `task_set.exe` 运行两个独立排程 Task；每 Task 限 8 次调用、
2 个 Run、60 秒、每请求输出 4096，启用该 Host 自有工具，未启用通用 shell。
示例在任何 Task wait 前输出 `host_available`，然后交回两个原始 Task 结果。

| 模式 | Task | Run 数 | 模型调用数 | 实际产物与 Host 校验 |
|---|---|---|---|---|
| controlled | background-0 | 2 | 5 | 排程 JSON；首次错误候选反馈修正，穷举最优检查通过 |
| controlled | background-1 | 2 | 5 | 同上；独立 Session 和工作区 |
| real model | background-0 | 1 | 6 | 排程 JSON；约束与穷举最优检查通过 |
| real model | background-1 | 1 | 5 | 排程 JSON；约束与穷举最优检查通过 |

真实路由使用本机既有授权代理。执行前 `GET /models` 确认
`deepseek-v4.1-flash`、`openai-completions` 和 tools 支持；凭据仅从环境读取。
两 Task 的适配器报告模型等待累计为 18,412/17,553 毫秒；各请求累计 token
21,614/16,617，包含重复上下文和缓存读取，不是独立输入量、账单或性能提升比例。
所选模型和路由已确认，未探查代理背后的内部供应商选择。

四个 Task 均为 `AwaitingHostAcceptance`、`task_accepted=false`、fence Released，
补充消息均为 `applied_to_context`。实际结果、消息回执、plan.json 及哈希保存在
[收据目录](task-set-20261101/summary.json)。完整原生 Session/事件及 Host 检查原件保留于
`D:/workspace/env/cache/task-set-validation-20261101-01a1945d/`。
主代理独立查看原 Host `Verified`/`Settled` 回执与实际排程文件；未用模型最终说明代替产物校验。

两次真实任务使用已有小型 reasoning fixture，不是陌生任务泛化测试；没有与单会话
实现做同预算 A/B，不能声称成功率、时延或 token 获得提升。
